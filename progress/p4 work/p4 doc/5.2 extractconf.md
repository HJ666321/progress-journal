### 第一行: 地址与元数据 (`000100010000000000000001`)

这一行的生成逻辑在 `emit-pkt.cpp` 的 `printStageInd` 函数中。该函数负责打印所有配置类型的头部信息。

**代码证据 1: `emit-pkt.cpp` 中 `printStageInd` 函数的结构注释**
```cpp
/*
 *  3B
 *  1B -- module ID [7:3] --> stage num, [2:0] --> module ID
 *  1B -- 4b mode, 4b reserved (used for two different components)
 *  1B -- index
 */
static void printStageInd(std::ostream &os, int module, int stg_num, int entry_ind, 
							int if_mask, int if_ram) {
	uint8_t module_id = (((uint8_t)stg_num)<<3 & 0b11111000) | (((uint8_t)module) & 0b00000111);
	uint8_t reserved = 0;
	uint8_t index = entry_ind;
    // ...
}
```
**分析**:
*   **第1个字节**: `module_id`。代码 `(((uint8_t)stg_num)<<3 ...)` 证明了它是由 **阶段号 (stage num)** 左移3位（占高5位）和 **模块号 (module ID)** （占低3位）组合而成。
*   **第2个字节**: `reserved`。保留/模式位。
*   **第3个字节**: `index`。即配置的索引或VID。

`KeyExtractConf` 在生成时，调用的是 `printStageInd(os, MODULE_EXTRACTOR, stage, vid, 0, 0)`。其中 `MODULE_EXTRACTOR` 在文件开头定义为 **1**。

**结论**: `00010001` (十进制17) 中，高5位 `00010` 是阶段号（**stage 2**），低3位 `001` 是模块号（**密钥提取器**）。第二个字节 `00000000` 是保留位。第三个字节 `00000001` 是VID（**1**）。这完全印证了我上一张表格中对第一行字符串的解释。

### `CAMMaskConf` - 深入代码的全面解析

#### 第一部分：地址与元数据

这部分由 `printStageInd` 函数生成。

**调用代码**:
```cpp
// emit-pkt.cpp: Line 113
printStageInd(os, MODULE_EXTRACTOR, stage, vid, 1, 0);
```
**代码解析**:
*   `module`: 传入的是 `MODULE_EXTRACTOR`，在文件开头定义为 `1`。
*   `stg_num`: `stage` 变量，由外部调用者传入。
*   `entry_ind`: `vid` 变量，由外部调用者传入，通常是VLAN ID。
*   `if_mask`: 传入的是 `1`。
*   `if_ram`: 传入的是 `0`。

`printStageInd` 函数内部逻辑如下：
```cpp
// emit-pkt.cpp: Line 38
static void printStageInd(...) {
    // ...
	uint8_t module_id = (((uint8_t)stg_num)<<3 & 0b11111000) | (((uint8_t)module) & 0b00000111);
	uint8_t reserved = 0;
	uint8_t index = entry_ind;

	if (MODULE_EXTRACTOR==module && if_mask) {
		reserved = 0xf; // 0xf is 15 in decimal, or 00001111 in binary
	}
    // ... prints module_id, reserved, index
}
```
**结论 (地址与元数据)**:
`CAMMaskConf` 的第一行24位字符串由此函数生成，其结构如下表所示。

| 比特段名称 | 长度 (比特) | 作用和说明 (代码依据) |
| :--- | :--- | :--- |
| **阶段号 (Stage Number)** | 5 | (来自 `stg_num` 变量) 左移3位，构成 `module_id` 的高5位。 |
| **模块ID (Module ID)** | 3 | `MODULE_EXTRACTOR` (值为`1`)，构成 `module_id` 的低3位。 |
| **保留/模式位 (Reserved/Mode)** | 8 | 因为 `if_mask` 为1，`reserved` 被设为 `0xf` (二进制 `00001111`)。 |

#### 第二部分：掩码数据

这部分紧跟在地址元数据之后，同样在 `printExtractorConf` 函数中生成。它的核心逻辑是根据一个名为 `key_conf.validity_flag` 的标志位来决定输出全`1`还是全`0`。

**调用代码**:
```cpp
// emit-pkt.cpp: Lines 115-139
if (key_conf.validity_flag & 0b100000) os << "0...0"; else os << "1...1"; // 48 bits for 6B_1
if (key_conf.validity_flag & 0b010000) os << "0...0"; else os << "1...1"; // 48 bits for 6B_2
if (key_conf.validity_flag & 0b001000) os << "0...0"; else os << "1...1"; // 32 bits for 4B_1
if (key_conf.validity_flag & 0b000100) os << "0...0"; else os << "1...1"; // 32 bits for 4B_2
if (key_conf.validity_flag & 0b000010) os << "0...0"; else os << "1...1"; // 16 bits for 2B_1
if (key_conf.validity_flag & 0b000001) os << "0...0"; else os << "1...1"; // 16 bits for 2B_2
// 192+1 = 193 bits
os << "1"; // last 1 cond bits
os << "0000000\n"; // append to 200bit = 25B
```

**代码解析**:
*   **逻辑**: 代码的逻辑很清晰：如果 `validity_flag` 的某一位被设置（通过 `&` 操作），则对应的掩码部分输出全`0`；否则输出全`1`。
*   **掩码含义**: 在TCAM中，`0`通常代表“忽略/Don't Care”，而`1`代表“必须匹配”。因此，`validity_flag` 标志着Key的某个部分**是否有效（是否参与比较）**。如果有效，则它的掩码为`0`（可以匹配任何值，因为Key的值会写入`CAMConf`）；如果无效，则它的掩码为`1`（必须匹配`CAMConf`中对应部分的值，通常是0）。
*   **总长度**: `48+48+32+32+16+16 = 192` 位。这192位对应了由 `KeyExtractConf` 定义的、可以组成Key的6个操作数。
*   **附加位**: 在192位掩码之后，代码固定输出一个 `1`，然后用7个`0`填充，最终形成一个200位的掩码数据。

**结论 (掩码数据)**:
`CAMMaskConf` 的第二行200位字符串结构如下表所示。

| 比特段名称                  | 长度 (比特) | 作用和说明 (代码依据)                          |
| :--------------------- | :------ | :------------------------------------ |
| **Mask for `op_6B_1`** | 48      | 由 `validity_flag` 的第6位 (0b100000) 决定。 |
| **Mask for `op_6B_2`** | 48      | 由 `validity_flag` 的第5位 (0b010000) 决定。 |
| **Mask for `op_4B_1`** | 32      | 由 `validity_flag` 的第4位 (0b001000) 决定。 |
